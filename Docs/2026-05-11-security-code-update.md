## 1. 구현 내용 (Feature Implementations)
- **보안 코드 랜덤 생성 버튼 추가**: 
  - 관리자 대시보드에서 수업 리소스 등록/수정 시, 패스워드(보안 코드) 입력창 우측에 랜덤 생성 버튼을 추가하였습니다.

- **보안 코드 전체화면 보기 기능 추가**:
  - 패스워드 입력창 우측에 크게 보기(전체화면) 버튼을 추가하였습니다.
  - 버튼 클릭 시 현재 입력된 보안 코드가 화면 전체를 덮는 커다란 텍스트 팝업(모달) 형태로 표시되어 교실 프로젝터 등을 통해 학생들에게 쉽게 안내할 수 있도록 하였습니다.
  - 빈 공간을 클릭하면 모달이 부드럽게 닫히도록 애니메이션을 적용했습니다.
- **보안 코드 가시성(보기/숨기기) 토글 기능 추가**:
  - 사용자(학생)가 코드를 입력할 때 오타를 방지하고 제대로 입력했는지 확인할 수 있도록, 보안 코드 입력창 우측에 눈 모양 아이콘(`Eye`, `EyeOff`) 토글 버튼을 추가했습니다.
- **가이드 열람 성공 피드백 UI 지연 노출 및 개선**:
  - 기존에는 새 창이 너무 빨리 열려 사용자가 성공 메시지를 볼 수 없었던 문제를 해결했습니다.
  - 올바른 코드를 입력하면 즉시 초록색 "코드 인증 성공! 가이드 페이지가 곧 열립니다!" 피드백 창으로 전환되며, 1.5초 동안 해당 메시지를 충분히 읽을 수 있도록 지연시간을 두었습니다.
  - 팝업 차단을 우회하기 위해 버튼 클릭 즉시 임시 로딩창을 띄워두고 1.5초 뒤에 실제 가이드 주소로 안전하게 리다이렉트 되도록 사용자 경험(UX)을 크게 개선했습니다.
- **참여 기관 정보 수정 기능 추가**:
  - 관리자 대시보드의 '참여 기관 관리' 메뉴에서 기존에 등록된 기관의 이름과 종류(Type)를 자유롭게 수정할 수 있는 기능을 추가했습니다.
  - 기관 목록 우측의 연필(Edit) 아이콘 클릭 시 해당 줄이 즉시 수정 폼(Input)으로 변경되며, 저장 시 백엔드(GAS)에 업데이트 되도록 구현했습니다.
- **기관 관리 작업 상태 알림(Toast) 추가**:
  - 기관 등록, 수정, 삭제 등의 작업이 완료되었을 때 화면 상단에 팝업 형태로 "성공적으로 저장되었습니다"와 같은 직관적인 피드백 알림을 표시하도록 UI를 보완했습니다.
- **리소스 목록에서 보안코드 바로보기 기능 추가**:

## 3. 해결된 에러 및 이슈 (Resolved Issues)
- **보안 코드 입력창 UI 잘림 현상 (CSS 갇힘 버그) 해결**:
  - **문제 원인**: `ResourceCard` 컴포넌트 최상단에 마우스 호버 시 카드 자체가 움직이는 애니메이션(`transform: translateY`)이 적용되어 있었습니다. 이 때문에 CSS 사양상 `position: fixed`로 설정된 모달창이 화면 전체(viewport)가 아닌 카드의 크기에 갇혀버리는 렌더링 버그가 발생했습니다.
  - **해결 방안**: React의 `createPortal`을 도입하여 모달 컴포넌트를 카드 내부가 아닌 `document.body` 레벨에서 독립적으로 렌더링되도록 분리하였습니다. 이제 어떤 환경에서도 모달창이 잘리지 않고 화면 정중앙에 정상적으로 표시됩니다.
- **올바른 코드를 입력해도 '일치하지 않는다'고 나오는 버그 해결**:
  - **문제 원인**: 관리자에서 생성한 랜덤 코드는 문자열(`string`)로 저장되지만, 구글 스프레드시트(GAS)를 거쳐 데이터를 받아오는 과정에서 순수 숫자형태로 캐스팅(`number`)되는 경우가 발생했습니다. 이로 인해 입력한 문자열과 비교(`===`)할 때 타입이 달라 일치하지 않음 오류가 발생했습니다.
  - **해결 방안**: 검증 로직(`password === passwordHash`)을 양쪽 모두 강제로 문자열로 변환하고 공백을 제거하는 로직(`password.trim() === passwordHash?.toString().trim()`)으로 수정하여 타입 불일치 및 공백 관련 버그를 원천 차단했습니다.
- **관리자 목록의 노션(Notion) 썸네일 이미지 깨짐(엑스박스) 문제 해결**:
  - **문제 원인**: 등록된 썸네일 URL 중 Notion의 첨부파일 이미지 링크(`https://www.notion.so/image/...`)를 렌더링할 때, 브라우저가 기본적으로 현재 웹사이트의 출처 정보(Referer)를 노션 서버로 함께 보내는데, 노션의 외부 임베드 보안 정책이 이를 차단하여 이미지 로딩이 실패(403 Forbidden)했습니다.
  - **해결 방안**: 썸네일을 렌더링하는 `<img>` 태그에 `referrerPolicy="no-referrer"` 속성을 추가하여 노션 서버에 Referer 정보를 보내지 않도록 조치함으로써 이미지가 정상적으로 노출되도록 해결했습니다.
- 기존의 단일 `input` 필드를 `flex` 컨테이너로 감싸고, `flex-1` 속성을 사용해 레이아웃이 깨지지 않도록 반응형으로 잘 조치되었습니다.
